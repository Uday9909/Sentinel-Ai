# Security Policy

## Supported Versions

| Version | Supported          |
|---------|--------------------|
| main    | ✅ Active development |
| < main  | ❌ Not supported     |

Only the `main` branch receives security updates. Patch releases are cut from `main` as needed for critical vulnerabilities.

## Reporting a Vulnerability

We take security seriously. If you discover a vulnerability, please **do not** open a public issue.

Instead, send a detailed report to **`writetoudaybir@gmail.com`**.

Please include:

- A description of the vulnerability and the potential impact
- Steps to reproduce (code, configuration, environment)
- Any suggested fixes (if known)
- Your name / affiliation for acknowledgment (optional)

You will receive a response within **72 hours** acknowledging receipt.

## Disclosure Policy

We follow a coordinated disclosure process:

1. **Report received** → acknowledgement within 72 hours
2. **Investigation** → we triage, reproduce, and develop a fix
3. **Fix prepared** → a patch is developed, reviewed, and tested
4. **Public disclosure** → 90 days after the fix is released, or earlier if a patch is deployed by the reporter

We ask that you refrain from sharing the vulnerability publicly until the 90-day window has elapsed or a fix has been released, whichever comes first.
